# 发布说明

## 当前发布方式：GitHub Actions

工作流位于 `.github/workflows/deploy-pages.yml`，GitHub Pages 的发布来源已设置为 GitHub Actions。

- 推送到 main：安装固定版本的依赖 → 从仓库内容源生成页面 → 严格构建 → 检查下载文件与站内链接 → 发布网站。
- Pull Request：执行同样的构建和检查，不发布网站。
- 也可在仓库 Actions 页面手动运行“检查并发布课程资料”。

构建只读仓库，发布任务使用 `pages: write` 与 `id-token: write`，不需要在仓库中保存个人令牌。检查失败会停止发布。公开内容源、插图与定稿文件均在仓库内，不依赖个人电脑路径。

## 本地预览

```powershell
python -m pip install -r requirements.txt
python 工具/构建站点.py
python -m mkdocs build --strict
python 工具/检查资料.py
python -m mkdocs serve
```

预览无误后提交并推送到 main，即可触发发布。依赖版本见 `requirements.txt`。

`gh-pages` 分支保留旧发布历史。当前使用 Actions 发布，不应再同时运行旧的 `mkdocs gh-deploy` 流程，以免两种发布方式互相覆盖。
